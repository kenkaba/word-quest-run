# Visual Benchmark Board — WORD QUEST RUN

最終更新: 2026-07-28 / 担当スキル: `visual-trend-researcher`

特定作品を模倣しない。複数ソースから**抽象的な成功原則**のみを抽出し、WORD QUEST 独自の具体策へ変換した記録。

## 0. 現状（Ver3.0）の直視

「幼稚」「安っぽい」を具体語に分解した結果:

| 症状 | 実際に起きていること（原因） |
|---|---|
| 背景が図形の集合に見える | すべての要素が**同一の彩度・コントラスト**で描かれ、奥行きによる減衰が無い |
| 空気感が無い | 空気遠近（霞）が地平の帯にしか無く、山・木・道に適用されていない |
| 光と影が平坦 | 光源方向が定義されておらず、全オブジェクトが単色 or 縦グラデのみ。陰influenceと影が無い |
| キャラが記号に見える | 脚が直線2本・膝が無い。髪とマントが本体と**同位相**で動くため布に見えない |
| 走行感が弱い | 上下 bob のみ。接地の瞬間の証拠（土煙・影の濃縮・カメラ沈み）が無い |
| 奥へ進む感覚が弱い | パララックス層が少なく、脇を流れるオブジェクトの密度と速度差が不足 |
| 質感が無い | 単色塗り。ノイズ・粒状感・面の分割が無い |
| モーションが機械的 | すべての揺れが同一の sin 波。位相差・遅延・減衰が無い |
| カタルシスが弱い | 成功/失敗の演出時間が短く、溜め（anticipation）と余韻が無い |

## 1. 起動3秒の第一印象

- **原則**: 2026年の市場は「はっきりした・自信のある・視覚的にコミットした」画面を評価する。曖昧な中間トーンは弱い。
- **具体策**: タイトルは静止画にせず、実際の世界が走り続けるデモを見せる。主色を2色に絞り、太陽/月の光源を画面内に置いてハイライトを作る。
- **検証**: タイトル撮影1枚で「時間帯」「場所」「主人公」が言えるか。
- 出典: [aaagameartstudio](https://aaagameartstudio.com/blog/mobile-games-art), [vsquad](https://vsquad.art/blog/new-trends-in-game-art-industry)

## 2. カメラ位置と画角

- **原則**: 速度感は FOV で作る。走ると FOV をわずかに広げると周辺が流れて加速感が出る。カメラは剛体追従せず遅れて追う。
- **具体策**: 遠近パラメータ `DEPTH` をコンボ速度で 6.2 → 7.4 へ動的変化。カメラ x はキャラ x を遅延追従（lerp 係数 0.06）。着地時に 6px 沈み込み。
- **検証**: 低速時と高速時のスクリーンショットで道の消失点付近の圧縮率が違うこと。
- 出典: [hackread juice](https://hackread.com/the-juice-factor-designing-game-feel/)

## 3. キャラクターの画面占有率

- **原則**: 主人公が小さいと感情移入が起きない。ただし画面下に沈むと足元が読めない。
- **具体策**: 全高を画面高の **16〜19%**、足元を画面高の **70〜73%** に置く（最下部へ沈めない）。
- **検証**: 撮影して足元と全身が見えること。

## 4. 背景の奥行き（最重要）

- **原則**: 空気遠近＝遠いものほど彩度・コントラストが落ち、**空の色へ寄る**。前景=シャープ、中景=遷移、遠景=霞。
- **具体策**: 深度 `z` に対する `hazeMix(z)` を作り、山・浮遊島・木・道・脇の props **すべて**に例外なく適用（近景0% → 地平0.85）。層は 前景/中景/遠景/最遠景 の4層。
- **検証**: 遠景の山と近景の木を並べて、彩度差が明らかにあること。
- 出典: [d5render](https://www.d5render.com/posts/atmospheric-perspective-for-aerial-rendering), [ecgprod](https://www.ecgprod.com/going-deep-art-techniques-show-depth/)

## 5. 色彩設計

- **原則**: ステージごとに限定パレット。色数を増やすほど安っぽくなる。
- **具体策**: 1ステージ = 主色2 + 差し色1 + 発光色1（Art Bible に固定）。
- **検証**: 実装の色定数がステージ定義の4色から派生していること。

## 6. 光と影

- **原則**: 3点照明（キー/フィル/リム）。2Dでもリムライトでシルエットが立つ。
- **具体策**: ステージごとに光源方向 `sunX`（-1..1）を定義。全オブジェクトは光源側が明・逆側が暗、逆光側の縁にリムライト。地面には接地影（足元ほど濃く小さい）。
- **検証**: 木・水晶・キャラに明暗の面が見えること。
- 出典: [gamineai rim light](https://gamineai.com/blog/lighting-2d-action-game-silhouettes-rim-ambient-shader-basics-2026)

## 7. 情報密度

- **原則**: 画面に置く情報を絞るほど高級に見える。
- **具体策**: HUD は距離・コンボ・ライフのみ（`visual-ui-guardian` が強制）。
- **検証**: 撮影して数えられる UI 要素が4つ以下。

## 8. 視線誘導

- **原則**: 明度と彩度が最も高い場所へ目が行く。
- **具体策**: 問題文と3択の板だけが画面内で最も高輝度。背景の発光は必ずそれ以下に抑える。
- **検証**: グレースケール化して最も明るい領域が問題と3択であること。

## 9. 質感

- **原則**: 単色塗りは平面に見える。粒状感・面分割・微細な明度差が「素材」を作る。
- **具体策**: 道と地面に微細ノイズの帯、遠景に霞の層、発光に多段グラデーション。ベタ塗り禁止。
- **検証**: 拡大して単一色のベタ面が支配的でないこと。

## 10. エフェクト

- **原則**: エフェクトは「情報」であるべき。意味のない発光は安っぽさの原因。
- **具体策**: 発光は「正解/選択中/自分の位置/重要CTA」に限定。環境の光は低彩度・低輝度に。
- **検証**: 発光要素それぞれに意味を1行で説明できること。

## 11. モーション

- **原則**: Disney の12原則、特に**フォロースルー（追従遅れ）**が重量感を生む。同位相の揺れは機械に見える。
- **具体策**: 髪・マント・裾は本体の動きを**遅延バッファ**で追う（本体と別位相）。着地に squash、跳躍に stretch。ヒットストップ（成功/失敗の瞬間に数フレーム止める）。
- **検証**: 連続フレームで髪と本体の位相がずれていること。
- 出典: [gamejuice Disney 12](https://gamejuice.co.uk/articles/disney-12-animation-principles-games)

## 12. UIと世界の融合

- **原則**: 四角い不透明パネルは世界を壊す。
- **具体策**: ガラス/結晶調（半透明・ぼかし・内側ハイライト・角丸）。答えは板ではなく道へ光の柱で接続。
- **検証**: UI を消しても世界が連続して見えること。

## 13. SNS動画で映える瞬間

- **原則**: 撮りたくなるのは「予想外の一瞬」。スロー・巨大・虹・数値の跳ね。
- **具体策**: 神回避スロー、コンボ節目の覚醒、100コンボの虹、巨大魔獣、宝箱。
- **検証**: 8場面の撮影に「明らかに他と違う画」が3つ以上あること。

## 14. 継続して見たくなる世界変化

- **原則**: 次の景色が報酬になる。
- **具体策**: 5ステージで空・地面・道・脇の props・光源色をすべて差し替え、切替時に閃光と地名表示。
- **検証**: 各ステージの撮影が別ゲームに見えるほど違うこと。
