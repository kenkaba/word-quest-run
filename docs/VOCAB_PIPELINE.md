# 語彙データ パイプライン — WORD QUEST RUN

最終更新: 2026-07-29

**方針**: 語彙数だけを増やさない。品質・重複防止・学習効果・ライセンス安全性を同時に満たす。

---

## 1. 議長決定（5人会議の結論）

**「辞書規模」ではなく「高頻度語 優先」で積み上げる。**

- **前提破壊役**が正しい: 一般英文の約92%は上位2,800語で覆える（NGSL の測定）。3万語の辞書ダンプより、頻出語を正確に覚えるほうが学習価値が高く、誤答生成の品質も保てる。
- **反対役**の懸念（大量投入で品質とライセンスが壊れる）を受け、**語彙を増やす前にパイプラインと検証を先に作る**。検証を通らないデータは入れない。
- **部外者役**の指摘（選択肢が不自然・同じ問題ばかり）が最優先の体感課題。よって初回は「重複防止」と「品詞一致の誤答」を先に完成させる。
- **拡張役**: 同じスキーマで他言語・資格試験・他教科へ展開できるよう、`pos` と `cat` を汎用にし、データとエンジンを分離した。

## 3. データ構造

`vocab.js` は転送量を抑えるため配列形式。`vocab-engine.js` が正規化する。

```
[ 英単語, 日本語訳, 品詞, 難易度, カテゴリ, 発音, 例文, 例文訳 ]
```

| フィールド | 値 |
|---|---|
| 品詞 `pos` | `n` 名詞 / `v` 動詞 / `adj` 形容詞 / `adv` 副詞 |
| 難易度 `lvl` | 1 Starter / 2 Basic / 3 Intermediate / 4 Advanced / 5 Expert / 6 Master |
| カテゴリ `cat` | food, nature, people, place, object, time, idea, emotion, motion, speech, mind, action, size, quality, feeling, freq, manner |

**実行時に付与される学習データ**（localStorage に永続化）:
出題回数 `seen` / 正解回数 `correct` / 不正解回数 `wrong` / 最終出題時刻 `lastAt` / 習熟度 `mastery`(0–1) / 再出題優先度（`priority()` で動的算出）

## 4. 重複防止ロジック

1. **直近リング**: 直近 `min(100, 語数×0.4)` 問に出た語を除外（現在98問）
2. **セッション内重複の禁止**: プールが40語超なら、同一プレイ中に出た語を再出題しない
3. **プール自動拡張**: 難易度で絞った結果が必要語数（120以上）に満たない場合、上限を自動で1段ずつ広げる。**語彙が少ないときの重複を構造的に防ぐ**（語彙が増えるほど拡張が不要になり、難易度進行が自然に効く）
4. **優先度つき重み抽選**: 苦手（誤答率が高い・習熟度が低い）ほど出やすく、覚えた語は出にくい。ただし直近1分以内は0.05倍、5分以内は0.4倍に抑え、**連発を防ぐ**
5. **正解位置の偏り補正**: 3レーンの出現数を記録し、72%の確率で最少レーンを選ぶ

## 5. 誤答生成

**品詞一致を絶対条件**にし、`apple → 走る` のような不一致を構造的に不可能にした。

優先順位: ①同じ品詞＋同じカテゴリ＋難易度±1（最も紛らわしい） → ②同じ品詞＋難易度±1 → ③同じ品詞＋難易度±2 → ④同じ品詞（全難易度）

同じ日本語訳は除外。正解と同一の訳も除外。

## 6. 3,000語 → 30,000語へ増やす手順

**手作業で大量生成しない。** 次の順で、各段階に検証を通す。

### Phase 1 → 3,000語（次の作業）

1. **語彙リストの取得**: NGSL（New General Service List, 2,809語, **CC BY-SA 4.0**, Browne/Culligan/Phillips）を採用候補とする。高頻度語で学習価値が最も高い。
   - 取得時は出典・バージョン・ライセンス全文を `docs/VOCAB_LICENSES.md` へ記録し、アプリ内クレジットに表示する（CC BY-SA は表示と同一ライセンス継承が条件）。
2. **日本語訳の付与**: ここが品質の要。機械的な自動対応は誤訳を生むため、
   - 品詞ごとに分割し、**1語1義（ゲームで問う意味を1つに確定）**して付与する
   - 多義語は「最頻出の1義」だけを採用し、残りは将来の別問題形式へ回す
3. **検証を通す**: `?selftest=1` の語彙ゲート（欠損0・重複0・品詞不一致0・誤答生成可能）を必ず全通過させる
4. **段階投入**: 500語ずつ追加し、都度セルフテストと実プレイで確認する

### Phase 2 → 10,000語

- 学術語彙（NAWL, CC BY-SA 4.0）やビジネス語彙（BSL）など、**ライセンスが明確なリスト**のみ追加
- カテゴリを細分化し、誤答の紛らわしさを維持する

### Phase 3 → 20,000〜30,000語

- ここで初めて辞書規模を検討する。候補は **JMdict/EDICT（EDRDG, CC BY-SA 4.0）** など。
- ただし辞書は語義が多く、そのままではゲームに使えない。**頻度順に上位から切り出し、1語1義へ落とす工程**が必須。
- 例文は **Tatoeba（CC BY 2.0 FR）** など出典明示可能なものから選定する。

### 禁止事項（厳守）

- 市販辞書・教材・アプリからのデータ流用
- ライセンス不明のデータセット
- 出典を記録しないままの取り込み
- 検証を通さないデータの投入

## 7. 分析指標（localStorage に記録）

`VocabEngine.report()` が返す:

- 平均回答時間 `avgAnswerMs`
- 難易度別の正答率と平均回答時間 `byLevel`
- 時間切れ率 `timeoutRate`
- プレイ中の重複率 `repeatRate`
- 1プレイあたりのユニーク単語数 `uniqueWords`
- 単語別のミス率（`stats` に `seen`/`wrong` として保持）
- 同一単語の再学習効果（`mastery` の推移）

直近50プレイ分を `wqr_analytics_v1` に保存する。
