# Visual Quality Gate

## 原則

**実装完了を自己申告で認めない。** 撮影と採点を経ていない変更は「完了」と呼ばない。

## 必須撮影（8場面）

1. タイトル画面
2. 通常走行
3. 3択出題中
4. 正解演出
5. 失敗演出
6. 高コンボ（10以上）
7. ボス画面
8. 結果画面

各場面を **375px / 390px / 430px** で確認する。
静止画だけでなく**連続フレーム**（同一場面を短間隔で複数枚）で動きを確認する。

## 撮影の実務

ブラウザプレビューは非表示中に requestAnimationFrame と viewport を止めるため、
同期実行だけで撮ると演出タイマーが凍って誤判定になる。必ず:

- `window.__WQR.calm()` で一過性演出を消してから素の画面を撮る
- 動きの確認は連続スクリーンショット（数枚）で位相差を見る
- 描画コストは `window.__WQR.bench()` で計測（目安: 5ms/frame 未満）

## 採点（各10点・合計100点）

| # | 項目 | 満点の条件 |
|---|---|---|
| 1 | 第一印象 | 起動3秒で「綺麗」と思える |
| 2 | 世界観 | 独自の世界に見える。既視感が無い |
| 3 | キャラクター魅力 | 記号でなく「人物」に見える。愛着が湧く |
| 4 | 奥行き | 空気遠近が効き、層が分離している |
| 5 | 躍動感 | 静止画1枚でも走っていると分かる |
| 6 | 視認性 | 最も派手な瞬間でも問題と3択が読める |
| 7 | 独自性 | 一目で WORD QUEST と分かる |
| 8 | SNS映え | 撮りたくなる瞬間がある |
| 9 | 商用品質 | 2026年の商用スマホゲームとして通用する |
| 10 | 次を見たい感情 | 次のステージ/景色を見たくなる |

## 判定

- **85点以上** … 浅井へ提出可
- **85点未満** … 提出禁止。低い項目の**原因を具体語で特定**し、再実装してから再採点

採点は甘くしない。根拠のない加点をしない。各項目に「なぜその点か」を1行書く。

## 完了条件

採点表・不合格理由・再実装内容が `docs/VISUAL_QUALITY_LOG.md` に追記されていること。
